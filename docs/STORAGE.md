# التخزين والملفات (Storage)

## ما وجدناه في iLogia الحالي
- مشروع Supabase: `zugwicbbfbefbbwugfxq` (نفس المفتاح العام `publishable` المستخدم في الموقع الحالي).
- مكتبة قديمة: جدول `library_items` + bucket اسمه `library` + دالة `get_library_file(p_item_id)` التي تتحقق من مجانية/اشتراك الملف على الخادم.
- لم نقرأ من المشروع الحقيقي ولم نكتب فيه. كل ما يلي مبني على ملفات الموقع الحالي (`supabase.js`, `INSTALL.md`).

## القرار
- **لا نلمس** bucket `library` ولا ملفاته. الملفات القديمة تظل مكانها، ويمكن استيراد صفوفها اختياريًا بملف `supabase/optional/20261031_legacy_import.sql` (مصدر `legacy`) فتُفتح عبر `get_library_file` ونفس قواعد الاشتراك.
- ملفات المكتبة الجديدة في bucket **خاص** جديد: `library-resources` (migration 002).

## القواعد المطبقة
| البند | التنفيذ |
|---|---|
| لا Public bucket | `public = false`. كل قراءة عبر **Signed URL** (10 دقائق للفتح/التحميل، ساعتان لقارئ PDF، ساعة للأغلفة). |
| صلاحيات القراءة | سياسة على `storage.objects`: الإدارة، أو صاحب الملف، أو أي مستخدم مسجّل **لمصادر منشورة فقط**. |
| الرفع | فقط لمن تعيد `library_can_upload()` له `true` (إدارة أو `profiles.is_teacher`)، وفقط داخل `u/<uid>/<resource-id>/file.<ext>`. |
| الحذف | الإدارة، أو صاحب الملف قبل نشره. |
| أنواع الملفات | قائمة سماح في الـ bucket (MIME) + في المتصفح (الامتداد + MIME + فحص أول البايتات). لا ملفات تنفيذية أو HTML أو SVG. |
| الحجم | 50 م.ب لكل ملف (`file_size_limit` + `MAX_FILE_BYTES`). **تأكد من حد خطتك** في Dashboard → Storage → Settings؛ لا يمكن لحد الـ bucket تجاوز حد المشروع. |
| أسماء الملفات | لا تُستخدم أسماء المستخدم في المسار أبدًا (`file.<ext>` فقط) فلا مسارات `..` ولا حروف عربية تكسر المفتاح. الاسم الأصلي يُحفظ كنص في `original_filename` بعد تنظيفه. |
| الأسرار | لا يوجد `service_role` في الواجهة. المفتاح المضمَّن هو المفتاح العام فقط. |
| انقطاع الشبكة | الرفع عبر **TUS** (استئنافي، قطع 6 م.ب، إعادة محاولة تلقائية + توكن جديد لكل طلب). عند فشل الرفع تُحذف الملفات الجزئية. |

## حدود يجب أن تعرفها (صراحةً)
1. **«منع التحميل» ليس DRM.** عندما `allow_download = false` نُخفي زر التحميل ولا نستدعي `download` في الرابط، لكن القارئ يحتاج بايتات الملف، فمن يعرف التقنية يستطيع حفظه. الإعداد يحترم رغبة الناشر في الواجهة وفي `library_track`، ولا يمنع النسخ تقنيًا.
2. فحص البايتات الأولى في المتصفح يكتشف الملفات المتنكرة، لكنه لا يغني عن مضاد فيروسات. إن احتجت فحصًا حقيقيًا فأضف Edge Function تفحص الملف عند الرفع (غير منفذ).
3. حذف مصدر يحذف ملفاته بمحاولة من المتصفح (best effort). إن فشلت تبقى ملفات يتيمة؛ نظفها دوريًا من Dashboard.
